# Claude 工具目录与完整定义按需加载

生产服务在本机制之前新增[请求体精简与固定工具白名单](PROMPT-OPTIMIZATION.md)。下文“所有名称可用”指经过当前配置白名单筛选后的工具；需要完整 MCP 目录时可设 QUICK_CLAUDE_TOOL_PROFILE=all。完整定义按需加载仍然生效。

2026-11-24 已部署服务器。适用于 Anthropic Messages 中客户端执行的外部 JSON schema 工具。API Key 与客户端请求协议不变，Quick 默认 high 思考不变。原 Responses 路径和 hosted 工具支持范围不在本次改动中。

## 设计取舍

单纯压缩长说明容易丢失语义，单纯缓存只能减少重复发送，不能降低首轮模型占用。现在将“发现有哪些工具”与“获取精确调用定义”分开。

当工具数量至少 8 个，或工具 JSON 超过 12000 字节，桥接服务器保留客户端这次提交的原始完整工具定义；Quick 首先只看到全量名称和每个工具约 100 UTF-8 字节的用途预览。不存在按熟悉名称删减工具的白名单。小工具集沿用现有 inline 模式。

模型通过内部 JSON 动作 tool_lookup 查询 1–4 个精确名称。服务器将对应原始 JSON 对象原样序列化，保留完整说明、嵌套字段说明、schema、枚举、引用、默认值与其他原始字段。只有加载过完整定义的工具才能返回给客户端执行。若模型直接猜测未加载工具的参数，桥接先提供完整定义，要求其重新生成，不转发第一次猜测。内部查询不会出现在 Claude 的工具执行列表中，也不会产生工具已执行的虚假结果。

完整定义仍以 JSON Schema 为权威；现有服务端仅覆盖常用约束的校验器不是完整 JSON Schema 实现，客户端仍须做自己的校验和审批。工具输出仍按数据处理。

## 缓存与会话

每次请求对原始完整定义计算版本指纹，包含描述和嵌套说明。当前请求保留完整定义，桥接缓存只追踪该原生会话已经加载的名称。后续相同设置且历史匹配时，只发送 NEW EVENTS；不反复发送目录和已经加载的定义。

API Key 在网关对应的用户 principal 隔离会话。定义变化、系统指令/工具选择变化、历史分叉、原生会话失效均不能沿用旧加载状态。原生会话恢复时先重新引导目录，再重新提供本次需要的完整定义。历史压缩改变前缀时也会建立新会话。工具载入不会被摘要伪造为仍然存在。

会话内使用越多工具，原生上下文中的已加载定义会逐步累积；服务器没有 API 可以删除 AWS 原生上下文中的单条旧定义。不能承诺“所有工具永远只有 3 KB”。重新引导后仅重新加载当前需要的定义。

## 字节预算与边界

目录上限 24000 UTF-8 字节，单批完整定义上限 56000 字节，最多四次内部查询和一次协议修复，均受请求总超时控制。过大的单项定义会明确报 413，不会通过裁剪约束来伪装支持。此版本未实现超大单工具定义分页或海量工具目录搜索。

QUICK_CLAUDE_TOOL_REGISTRY=0 可关闭该机制，重启 quick-codex 后回到上一版 inline 方案；程序参数 createBridge({toolRegistry:false}) 也可关闭。

首次调用一个工具可能增加一次 Quick 往返。AWS 三条活动连接上限仍然适用，客户端可能等待重试。此版本不宣称延迟降低或账单 token 按相同比例降低。

非流式公网响应头 x-quick-tool-registry=on 标识启用，x-quick-tool-definition-count 为本次完成后原生会话已加载数量，x-quick-request-total-bytes 为该 HTTP 请求内送往生成后端的提示字节累计（包含内部查询/修复；不含预先的历史摘要）。x-quick-sent-chars 仍只表示最后一次生成调用字符数。字节数不是账单 token。Messages 流式响应自 2026-11-24 起提前发送 message_start 和等待心跳，开始后才得到的统计不能再写入 HTTP 响应头，请查看服务端完成日志。

## 量测与真实验证

保存的同一 24 工具样本：原工具 JSON 75445 字节；目录 3070 字节。使用相同系统指令和短任务，上一版 inline 首轮提示 24458 字节，新版 8925 字节，首轮减少 63.51%。Read 完整定义 1923 字节，Write 639 字节，实际加载时另有短协议包裹。量测没有修改用户指令以获得更低数字。

真实 Claude CLI 经隔离桥接、携带全部 24 工具目录，完成 Glob → Read → Edit → Write → Bash，真实文件被修复为乘法，result.txt=437，测试输出 REGISTRY_REAL_TEST_OK，进程退出 0。耗时 96.2 秒；遇到三次 AWS 429 和四次原生会话恢复，总发送 111441 字符。该数据没有可比的旧版完整运行对照，不能作为端到端流量或速度提升证据。

生产公网 25 工具目录测试：MCP 风格 mcp__registry_probe__calculate 加载后生成精确 expr=41*13，服务器实际执行返回 533，随后完成工具结果续接。首个 HTTP 请求累计生成提示 6414 字节，已加载工具数 1。该测试验证协议适配，不代表实际安装的所有 MCP 服务均已逐一执行。

42 项 Node 回归通过，新增覆盖完整原始定义保留、目录缩小、未知工具、none/强制工具、直接猜参拦截、重复查询限制、跨用户隔离、指纹变化、原生会话恢复及超大定义错误。真实 VS Code 完整交互 UI 仍未逐项验证。
