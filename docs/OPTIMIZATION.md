# 会话复用与输入减重实测

## 2026-11-22 改动

1. Chat Completions 通过调用者和精确历史前缀复用原生 Quick 会话；Responses 使用随机内部 session ID、revision 和 previous_response_id 链。续轮只发送新增事件，保留一轮中的多个新增工具结果。
2. 工具描述转为紧凑函数签名，保留必填、类型、枚举及其他约束。默认核心工具过滤保持启用，custom 格式定义不随意丢弃。
3. 外部客户端协议包装固定五行，客户端 instructions 不截断。
4. 工具返回值限制 2000 字符，保留头部 500、截断标记及剩余尾部。整条 JSON 事件还包含 call_id 等字段，因此其总长度可略高于 2000。

## 真实 AWS 验证

在隔离端口完成测试后才替换生产代码，未将模拟模型输出当成执行结果。

| 检查 | 实测结果 |
| --- | --- |
| 三轮聊天记忆 | 3 次请求共用 1 个原生会话；后两轮都记得随机 token |
| 普通聊天续轮 | 各发送 65 字符，没有重发初始历史 |
| 外部编程工具循环 | 4 个 Node 命令实际执行，exit_code 全为 0，最后一轮校验全部结果 |
| 编程循环会话数 | 5 次模型请求共用 1 个原生会话 |
| 编程循环消息长度 | 1333、152、152、152、2123 字符 |
| 长输出 | 实际 stdout 5009 字符，工具值截为 2000；连同事件结构为 2123 字符 |

四个命令依次计算 11+31、7*8、99-2，并运行只输出长日志的本地测试文件。执行器只接受这四条固定命令，通过 execFileSync 执行，不执行模型任意生成的 shell 代码。最终回答必须包含初始随机标记、42、56、97 和日志尾部标记，因此也验证了增量工具事件后的上下文记忆。

## 长工具描述压力样例

该样例使用**人工构造的冗长 exec_command 描述**，然后实际请求 AWS；它不是所有 Codex 请求的固定缩减率。

| 指标 | 字符数 |
| --- | ---: |
| 原工具 JSON | 201267 |
| 紧凑工具签名 | 148 |
| 旧版首轮完整提示 | 203768 |
| 新版首轮实际发送消息 | 1333 |
| 首轮减少比例 | 99.35% |

instructions 本身很长或 custom 格式定义较大时，减少比例会不同。不能承诺所有请求都减少 70%。

## 验证时遇到的限制

最初因 AWS 活跃连接最多 3 条而被拒绝，释放闲置客户端后继续验证。包含内联长输出代码的工具任务曾被上游内容过滤拒绝；该失败没有计为通过。成功测试改用实际的本地长日志测试文件，上游内容过滤仍可能拒绝其他任务，适配器不会屏蔽或绕过该错误。

会话表最多 100 项，空闲 30 分钟过期。换指令、换工具集、历史分支、取消/失败、服务重启和缓存丢失可能触发完整上下文重建；这不是“永远只创建一个对话”。已有重复记录不会自动删除。
